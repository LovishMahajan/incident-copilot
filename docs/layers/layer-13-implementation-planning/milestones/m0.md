## Deviations

1. **No tagged CI run, no secret scan, no required checks.** Criterion 7 is not met (above). Branch protection, which makes the checks required (T0.4), needs the repository's settings and a person with access.
2. **Temporal "UI" shown without the UI page.** The workflow was read through the `temporal` CLI (admin-tools image) and through the HTTP API the UI serves, at the same address. Nobody looked at the page.
3. **Docker's layer cache.** `docker compose up --build` in the clone reused image layers built earlier on this machine from the same files. The clone's checkout and `.venv` were new.
4. **The scripted path.** The scripted `draft_patch` answers `no_allowed_fix`, so the incident goes `diagnosed` → `handed_over` and never reaches `testing`. Release A's tested-recommendation path (`testing` → `handed_over`) needs action rows, which M0 doesn't write; it is tested offline in `tests/unit/test_workflow.py`. `record_transition`'s action status updates are built but no test exercises them against PostgreSQL yet.
5. **Demo pacing.** `AISRE_SCRIPTED_STEP_SECONDS` (0 to 10, default 0) was added so the worker kill lands mid-run; without it the scripted run takes about half a second.
6. **One event per state change, and a `status_changed` for same-state writes.** `record_transition` writes `aisre.incident.status_changed.v1` for each transition, including a write that changes only an action, where `from_status` equals `to_status`; Artifact 7.5's action events (`aisre.action.*`) come with the modules that own them (M2, M3). The hand-over writes both the `status_changed` into `handed_over` and `aisre.incident.handed_over.v1`.
7. **`docker compose start worker`** also reruns the one-shot jobs (schema, namespace, migrations), which change nothing on a second run.
8. **Who ran it.** A coding agent ran the demo; Artifact 13.12 does not count that as the Platform owner's confirmation.
